# Lessons Carried Over From `forex-trading`

This document records concrete, verified mistakes made in the predecessor
`forex-trading` codebase, and the specific engineering countermeasure adopted
in this repository for each. Source: `forex-trading/docs/decade_strategy_health_check_2026-07.md`
and `forex-trading/logs/dashboard_err.log`, audited 2026-07-28.

## 1. Silently dead strategies in live trading

Three of nine enabled forex strategies never actually fired in live trading
because the `MarketSnapshot` fields they depended on were never populated by
`DataEngine`, and nobody noticed for months:

- `has_volume_spike_60m` was never set by any code path → always `False` →
  `volume_climax` (the *only* strategy with a real gross edge in the decade
  study) could never trigger live.
- `vol_ratio` was pinned to a `1.0` sentinel (no real volume from the REST feed)
  → `vwap_momentum`'s confidence score could never clear its own threshold.
- `breakouts_today`'s increment condition was structurally close to unreachable
  live (the forming candle already contains the tick being tested against it).

**Countermeasure**: `tests/test_wiring_parity.py` — for every strategy, statically
collect every `MarketSnapshot` / `MarketState` attribute it reads, then assert the
live `DataEngine` code path actually assigns a non-default value to each of those
attributes under realistic input. This must pass in CI before a strategy can be
marked `enabled: true`.

## 2. Dead configuration keys

`auto_execute` existed in `configs/strategy.yaml` for a period with **no code
that read it** — the observe-only safety switch was a no-op.

**Countermeasure**: `tests/test_config_enforcement.py` — every guard-like key in
`configs/*.yaml` must have a matching test that (a) locates the exact line that
reads the key and (b) proves the key's value changes behavior.

## 3. Timestamp unit bug corrupting a decade of research

The Dukascopy tick loader treated microsecond timestamps as nanoseconds,
shrinking simulated holding times by 1000x and silently disabling the stale-exit
logic for an entire multi-week research cycle before being caught.

**Countermeasure**: any timestamp parsing/conversion goes through one central
function (`python/core/timeutil.py`) with a hard assertion that the resulting
year is in `[2000, 2100]`; unit tests cover every data source's native unit.

## 4. Transaction costs structurally dominate the edge

All nine strategies had negative live net expectancy — round-trip cost
(0.2–0.4R per trade) exceeded gross edge in every case except a thin,
mechanically-explained slice of `volume_climax`.

**Countermeasure**: acceptance gate in `configs/goal.yaml` — a strategy needs
**gross expectancy ≥ 2× round-trip cost** measured on the *same* backtest before
it is eligible for `auto_execute: true`. See `backtests/reports/us_equity_health_check.md`
(generated by `scripts/run_backtest.py`) for the live gate values.

## 5. Unthrottled API polling burned rate limits all day

`dashboard_err.log` shows Alpha Vantage's 25 requests/day limit being hit and
then re-polled every ~15 seconds for the rest of the day, producing thousands
of wasted 429-equivalent log lines.

**Countermeasure**: `python/core/rate_limiter.py` — a central token-bucket
limiter per external API; once a hard daily quota is hit, polling stops and a
single alert fires instead of continuous retry.

## 6. Live vs backtest divergence went undiagnosed for a long time

`range_bounce` showed +0.895R/trade live vs -0.11R/trade in the decade backtest
— a direct contradiction that sat unresolved because nothing compared the two
systematically (this is exactly Chan Ch.5's "why does live diverge from
backtest" diagnostic list, which was never automated).

**Countermeasure**: `python/core/reconciliation.py` — a daily job that replays
each day's actual fills through the same feature/signal pipeline used in
backtest and flags any qualified-signal / fill-price / P&L delta beyond a
tolerance.
